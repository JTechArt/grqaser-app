# Story 10.1: App Launch Performance and Lazy Load

## Status

Draft

## Story

**As a** mobile user,
**I want** the application to open very quickly without loading all books and images into memory,
**so that** I can start using the app without long waits and the app remains responsive.

## Acceptance Criteria

1. **Fast app open:** The app launches and becomes usable quickly; initial load does not wait for the full catalog or all images to load.
2. **Lazy load catalog:** Book list/catalog data is loaded lazily (e.g., paginated or on-demand), not all books loaded into memory at once.
3. **Collection size from DB:** Where the UI needs the count of books (e.g., collection size), the app uses a count query (e.g., `getCount`) from the database instead of loading all books and then computing the size.
4. **No full preload of images:** Initial launch does not preload all book cover images; images are loaded as needed (lazy load).
5. No regression in browse, search, Library, or playback once data is loaded.

## Tasks / Subtasks

- [ ] Task 1: Identify and fix full catalog load at launch (AC: 1, 2)
  - [ ] Locate where catalog/books are loaded on app start (e.g., Redux init, home screen, catalog slice)
  - [ ] Replace "load all books" with lazy/paginated loading (e.g., load first page or load on screen focus)
  - [ ] Ensure app shell becomes interactive before any large data fetch completes

- [ ] Task 2: Use getCount (or equivalent) for collection size (AC: 3)
  - [ ] Find all places that derive "number of books" or collection size by loading full list (e.g., Library count, catalog count)
  - [ ] Add or use a DB count query (e.g., `getCount` in repository/service) and use it for display
  - [ ] Remove any pattern that loads all books only to get length/size

- [ ] Task 3: Ensure no full image preload at launch (AC: 4)
  - [ ] Verify cover images are not preloaded for entire catalog on launch
  - [ ] Ensure cover loading is deferred to when lists/screens are shown and images are in view (align with Story 10.6 if needed)

- [ ] Task 4: Verify no regressions (AC: 5)
  - [ ] Test browse, search, Library, and playback after data is loaded
  - [ ] Confirm launch time improvement (e.g., time to interactive) is measurable

## Dev Notes

### Context

Application currently loads too long on open; likely causes include loading all books into memory and loading images up front. Goal: fast time-to-interactive, lazy catalog load, and use DB count for collection size instead of loading all books.

### Relevant Source Tree

```
GrqaserApp/src/
├── state/slices/           ← catalog/library slices may load full list on init
├── database/ or services/  ← add or use getCount for books/collection
├── screens/                ← Home, Library, etc. may trigger full load
└── (see architecture docs for exact paths)
```

### Key Areas to Check

- **App bootstrap / Redux initial state:** Ensure no thunk or effect loads full book list on app start.
- **Catalog/books repository:** Add `getBookCount()` or equivalent that runs `SELECT COUNT(*)` (or similar) instead of `SELECT *` then `.length`.
- **Library/catalog UI:** Use pagination or "load more" / virtual list so only visible or first N items are fetched initially.
- **Cover images:** Handled in Story 10.6; ensure launch path does not preload all covers.

### Testing

- Measure time to interactive before and after (e.g., with 500+ books in DB).
- Verify collection size in UI matches DB count without loading all rows.
- Verify browse, search, Library, playback still work after lazy load.
