# Story 10.4: Offline Support and Connection Status

## Status

Draft

## Story

**As a** mobile user,
**I want** the application to work without internet when I have downloaded books, and to see clear connection status,
**so that** I can open the app and listen offline, and I know when the connection has failed or been restored.

## Acceptance Criteria

1. **Open without network:** The app opens and is usable without an internet connection; network is not required to launch the app.
2. **Offline listening:** If the user has downloaded books, they can browse and play them when offline.
3. **Connection-failed warning:** When the device has no (or lost) connection, the app shows a clear warning that the network connection failed (e.g., banner or notification).
4. **Connection recovery:** The app pings (or checks) connection state periodically (e.g., every 10 seconds); when the connection is restored, the app shows that it is fixed and removes the "connection failed" notification.
5. No blocking of app usage when offline for already-downloaded content; only appropriate warnings and optional features (e.g., catalog refresh) may be disabled.

## Tasks / Subtasks

- [ ] Task 1: Ensure app opens without network (AC: 1)
  - [ ] Remove or defer any startup logic that requires network (e.g., mandatory API call, auth) so app renders without waiting for network
  - [ ] Ensure local DB and stored data are available without network; app shell loads from local state only on launch

- [ ] Task 2: Verify offline playback and browse (AC: 2)
  - [ ] Confirm downloaded books are playable when device is offline
  - [ ] Confirm catalog/Library list from local DB works offline; no blocking on network

- [ ] Task 3: Show connection-failed warning (AC: 3)
  - [ ] Integrate or add network state detection (e.g., NetInfo or equivalent)
  - [ ] When connection is unavailable, show a clear "Network connection failed" (or similar) warning (banner, toast, or inline message)
  - [ ] Do not block UI; allow user to continue using offline content

- [ ] Task 4: Periodic check and recovery notification (AC: 4)
  - [ ] Implement a periodic check (e.g., every 10 seconds) for connection state
  - [ ] When connection is restored after being failed, show a brief "Connection restored" (or similar) and then remove both the failed and restored notifications
  - [ ] Ensure only one active warning at a time and clean removal when fixed

- [ ] Task 5: Verify no blocking and optional features (AC: 5)
  - [ ] Ensure catalog refresh, DB update, or other network-dependent features are disabled or show "offline" message when appropriate, but do not block opening or playing downloaded content

## Dev Notes

### Context

App should work fully offline for downloaded content; network is not required to open the app. User should see when connection fails and when it is fixed, with a 10s ping to update state.

### Relevant Source Tree

```
GrqaserApp/src/
├── App.tsx or root       ← avoid blocking on network at mount
├── state/slices/        ← optional: networkStatus slice
├── services/            ← network check (e.g., NetInfo), ping interval
├── components/          ← connection banner / notification
└── screens/             ← ensure no screen blocks on network for local data
```

### Key Points

- **NetInfo (React Native):** Use `@react-native-community/netinfo` or equivalent to get connection state and subscribe to changes.
- **Ping interval:** Use setInterval (e.g., 10s) to re-check connection and update UI; clear interval on unmount.
- **UX:** "Connection failed" when offline; "Connection restored" when back online, then dismiss both. Do not block navigation or playback of downloaded books.

### Testing

- Open app with WiFi/cellular off: app opens, local data visible, downloaded books playable.
- With app open, turn network off: warning appears; turn network on: "restored" then dismiss.
- Verify 10s interval updates state (e.g., turn network on after 5s and within 10s see "restored").
