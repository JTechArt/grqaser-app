# Story 10.2: Library Section — Layout, In Progress, and Download Progress

## Status

Draft

## Story

**As a** mobile user,
**I want** the Library section to have consistent layout and reliable behavior for all subsections (All, In Progress, Downloads),
**so that** section buttons stay correctly sized, In Progress shows my opened books reliably, and I see download progress clearly.

## Acceptance Criteria

1. **Section button sizing:** When there are more than five books in Library, section buttons (e.g., All, In Progress, Downloads) do not become smaller; padding and margin are correct so the layout remains consistent at any book count.
2. **In Progress reliability:** The "In Progress" section reliably shows books the user has opened (e.g., opened yesterday or today); the list is consistent and not sometimes empty when it should show items.
3. **Download section with progress:** When a download is started, the book appears in the Download section with an overlay (or clear indicator) showing the download percentage (e.g., "45%") until complete.
4. No regression in other Library behavior (e.g., removing items, opening books).

## Tasks / Subtasks

- [ ] Task 1: Fix Library section button layout with 5+ books (AC: 1)
  - [ ] Inspect Library screen layout (e.g., section tabs/buttons) and identify padding/margin or flex that causes shrinking when many books
  - [ ] Apply fixed or min dimensions / padding so section buttons do not shrink (e.g., consistent height, padding)
  - [ ] Test with 5, 10, 20+ books to confirm layout stays consistent

- [ ] Task 2: Fix In Progress section reliability (AC: 2)
  - [ ] Locate how "In Progress" list is populated (e.g., from progress table, last-opened, or library with progress)
  - [ ] Fix any bug where opened books are not recorded or not queried correctly (e.g., date/time, DB query, state)
  - [ ] Verify books opened across sessions (e.g., yesterday vs today) appear consistently

- [ ] Task 3: Download section percent overlay (AC: 3)
  - [ ] Ensure when a download is started, the book appears in the Download section immediately (or as soon as first chunk starts)
  - [ ] Add overlay or inline indicator showing download percentage (e.g., "45%") that updates until 100%
  - [ ] When download completes, show as complete (no percentage or "Complete" state)

- [ ] Task 4: Verify no regressions (AC: 4)
  - [ ] Test removing items from Library, opening books, and other Library flows

## Dev Notes

### Context

Library section has three issues: (1) section buttons get smaller with more than 5 books (padding/margin), (2) In Progress sometimes shows opened books and sometimes does not, (3) Download section does not show in-progress downloads with percent. Fix layout and data/state logic.

### Relevant Source Tree

```
GrqaserApp/src/
├── screens/
│   └── LibraryScreen.tsx (or equivalent)  ← section buttons, layout
├── state/slices/                           ← library, progress, download state
├── components/                            ← list items, download row, overlay
└── (see architecture for progress/download persistence)
```

### Key Areas to Check

- **Section buttons:** Likely a horizontal list or tabs; check `flexShrink`, `padding`, `minWidth`, or parent flex that causes compression when content grows.
- **In Progress:** Check how "opened" or "in progress" is stored (DB table, AsyncStorage, Redux) and how the list is queried; fix missing writes or wrong query (e.g., filter by date range, limit).
- **Downloads:** Download state may be in Redux or a service; ensure active downloads are visible in Library Download section and progress (percent) is passed to UI for overlay.

### Testing

- Manual: Add 5+ books to Library, confirm section buttons size; add 10, 20, confirm no shrink.
- Manual: Open several books, close app, reopen; confirm In Progress shows them; repeat across days if applicable.
- Manual: Start a download, confirm book in Download section with % updating until complete.
