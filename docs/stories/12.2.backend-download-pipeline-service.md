# Story 12.2: Backend download pipeline service

## Status

Done

## Story

**As an** administrator,  
**I want** a download pipeline that creates folder structure, writes metadata for each book, then downloads MP3 files with storage-limit checks and progress tracking,  
**so that** I can bulk-download audiobooks in ordered phases with auto-pause when storage limit is reached.

## Acceptance Criteria

1. Pipeline runs in three phases: (1) Create base folder structure and validate write permissions, (2) Create per-book folders and write metadata.json for each book, (3) Download MP3 files for each book.
2. Before adding a book to the current batch, check that current_batch_size + book_estimated_size <= max_size; if exceeded, pause the batch automatically.
3. Each book folder structure: `{base_folder}/{book_id}_slug/metadata.json`, `part_001.mp3`, `part_002.mp3`, etc.
4. metadata.json contains all required fields per feature spec: id, title, author, description, duration, grqaser_url, cover_image_url, main_audio_url, chapter_urls, download_links, etc.
5. Progress is persisted to admin_downloaded_books and admin_download_batches; status updates reflect phase, book, part, size.
6. Failed book downloads are logged, marked as failed, and do not stop the batch; next book continues.
7. Admin can cancel a running batch; partial progress (metadata + completed MP3s) is retained.

## Dev Notes

### Context

Epic 12 MP3 bulk download. This story implements the core pipeline logic; Story 12.3 adds API endpoints; Stories 12.4–12.5 add UI ([Source: docs/feature-requests/mp3-bulk-download-admin.md]).

### Books table reference

- Single-file: `main_audio_url`
- Multi-chapter: `chapter_urls` (JSON array), `chapter_count`, `has_chapters`
- Other: id, title, author, description, duration, duration_formatted, cover_image_url, file_size ([Source: docs/architecture/data-models-and-schema.md])

### metadata.json required fields

id, title, description, author, duration, duration_minutes, grqaser_url, cover_image_url, main_audio_url, chapter_urls, chapter_count, category, language, published_at, download_links (array of URLs) ([Source: docs/feature-requests/mp3-bulk-download-admin.md])

### Estimated book size

Use `file_size` from books table if available; else estimate ~1MB per minute or fetch Content-Length header when starting download ([Source: docs/feature-requests/mp3-bulk-download-admin.md]).

### File locations

- **Pipeline service:** `books-admin-app/src/services/download-pipeline.js` (or similar)
- **Config:** max_size_bytes default 200 * 1024 * 1024 * 1024 (200GB)

### Compatibility

- One active download batch at a time ([Source: docs/feature-requests/mp3-bulk-download-admin.md NFR]).

### Testing

- Integration test: run pipeline against test DB and temp folder; verify structure and metadata

### Refactoring Performed

- **File**: `books-admin-app/src/services/download-pipeline.js`
  - **Change**: Fixed Phase 2 and Phase 3 loops to use `manifestWithUrls[i]` instead of `manifestList[i]`. Previously, when iterating over `manifestWithUrls` (filtered list of books with valid URLs), the code incorrectly indexed `manifestList`, causing wrong books to be processed when some books had no valid download URLs.
  - **Why**: Would create folders and metadata for wrong books when scope included books without main_audio_url/chapter_urls.
  - **How**: Use `manifestWithUrls` consistently for both phases; progress counts now reflect actual downloadable book count.

- **File**: `books-admin-app/tests/download-pipeline.test.js`
  - **Change**: Added test "Phase 2 skips books with no valid URLs" — verifies that when scope includes book 1 (no URLs), only book 2 (with URLs) gets folder and metadata.
  - **Why**: Regress the manifest index bug.
  - **How**: Insert book 1 without main_audio_url; assert only 2_book-two folder exists.
