# Story 11.1: Defer Database Initialization

## Status

Done

## Story

**As a** user,
**I want** the app to open immediately and show UI,
**so that** I don't have to wait 30 seconds staring at a blank screen.

## Acceptance Criteria

1. App UI renders within 1-2 seconds regardless of network state
2. Database initialization runs asynchronously after UI is visible
3. Loading state shown while databases initialize
4. User can see app structure immediately (navigation, header, etc.)
5. Data loads progressively as databases become available
6. Graceful error handling if initialization fails

## Dev Notes

### Current Flow (Blocking)

```
HomeScreen mounts → useEffect runs → initializeDatabases() BLOCKS ~30s → fetchBooksPage → UI shows data
```

User sees blank/frozen screen during init when network is available. [Source: docs/prd/epic-10.md]

### New Flow (Non-Blocking)

```
App.tsx mounts → dispatch(initializeDatabases()) fire-and-forget
NavigationContainer + screens render immediately
HomeScreen shows loading state until dbInitialized
(In background) initializeDatabases completes → dbInitialized true → fetchBooksPage → UI updates
```

[Source: docs/prd/epic-10.md#New-Flow]

### Implementation Reference

**App.tsx:**
```typescript
useEffect(() => {
  dispatch(initializeDatabases());  // Fire and forget
}, [dispatch]);
```

**HomeScreen.tsx:**
```typescript
useEffect(() => {
  if (dbInitialized) {
    dispatch(fetchBooksPage({limit: 20, offset: 0}));
    dispatch(fetchCatalogStats());
  }
}, [dispatch, dbInitialized]);
```

**Loading UI:** Show ActivityIndicator + "Initializing catalog..." or "Loading catalog..." when `!dbInitialized`. [Source: docs/prd/epic-10.md]
