# Story 11.1: Defer Database Initialization

## Status

Draft

## Story

**As a** user,
**I want** the app to open immediately and show UI,
**so that** I don't have to wait 30 seconds staring at a blank screen.

## Acceptance Criteria

1. App UI renders within 1-2 seconds regardless of network state
2. Database initialization runs asynchronously after UI is visible
3. Loading state shown while databases initialize
4. User can see app structure immediately (navigation, header, etc.)
5. Data loads progressively as databases become available
6. Graceful error handling if initialization fails

## Tasks / Subtasks

- [ ] Task 1: Move initializeDatabases to App.tsx (AC: 1, 2)
  - [ ] In `GrqaserApp/App.tsx`, add `useEffect` that dispatches `initializeDatabases()` without awaiting.
  - [ ] Use `dispatch(initializeDatabases())` — fire and forget; do not block render.
  - [ ] Remove or defer any code that blocks render until init completes. [Source: docs/prd/epic-10.md#Implementation-Changes]

- [ ] Task 2: Make initialization non-blocking (AC: 2)
  - [ ] Ensure `initializeDatabases` thunk does not block the main thread; run DB init asynchronously.
  - [ ] Verify NavigationContainer and root UI render before init completes.
  - [ ] Do not await `initializeDatabases` in App.tsx. [Source: docs/prd/epic-10.md]

- [ ] Task 3: Add splash/loading screen (AC: 3, 4)
  - [ ] Create `AppLoadingScreen` component (or equivalent): ActivityIndicator + "Loading catalog..." text.
  - [ ] Show when `dbInitialized === false` and `loading === true` from databaseSlice.
  - [ ] Place in appropriate wrapper (e.g. RootNavigator or AppContent) so user sees app structure (nav, header) or a clean loading state—per epic: "User can see app structure immediately."
  - [ ] Clarification: Epic says "show app structure (navigation, header)" — implement so navigation shell is visible with loading indicator inside, not a full-screen block. [Source: docs/prd/epic-10.md#New-Flow]

- [ ] Task 4: Update HomeScreen to check initialization state (AC: 5)
  - [ ] Remove `initializeDatabases` call from HomeScreen useEffect.
  - [ ] HomeScreen only fetches books/stats when `dbInitialized === true`.
  - [ ] When `dbInitialized === false`, show loading state (or parent handles it).
  - [ ] Ensure HomeScreen does not trigger init; App.tsx owns init. [Source: docs/prd/epic-10.md]

- [ ] Task 5: Defer data fetching (AC: 5)
  - [ ] `fetchBooksPage` and `fetchCatalogStats` run only after `dbInitialized` is true.
  - [ ] HomeScreen useEffect: `if (dbInitialized) { dispatch(fetchBooksPage(...)); dispatch(fetchCatalogStats()); }`.
  - [ ] If not initialized, show loading UI (per Task 3). [Source: docs/prd/epic-10.md]

- [ ] Task 6: Graceful error handling (AC: 6)
  - [ ] If `initializeDatabases` fails (rejected), set error state in databaseSlice.
  - [ ] Show user-facing error message (e.g. "Failed to load catalog. Please check your connection and try again.") with retry option.
  - [ ] Do not leave user on endless loading. [Source: docs/prd/epic-10.md]

- [ ] Task 7: Unit tests
  - [ ] Test App.tsx dispatches initializeDatabases on mount.
  - [ ] Test HomeScreen does not call initializeDatabases; only fetches when dbInitialized.
  - [ ] Test loading and error states.
  - [ ] Run `npm test` from GrqaserApp. [Source: architecture/testing-and-deployment-strategy.md]

## Dev Notes

### Current Flow (Blocking)

```
HomeScreen mounts → useEffect runs → initializeDatabases() BLOCKS ~30s → fetchBooksPage → UI shows data
```

User sees blank/frozen screen during init when network is available. [Source: docs/prd/epic-10.md]

### New Flow (Non-Blocking)

```
App.tsx mounts → dispatch(initializeDatabases()) fire-and-forget
NavigationContainer + screens render immediately
HomeScreen shows loading state until dbInitialized
(In background) initializeDatabases completes → dbInitialized true → fetchBooksPage → UI updates
```

[Source: docs/prd/epic-10.md#New-Flow]

### Implementation Reference

**App.tsx:**
```typescript
useEffect(() => {
  dispatch(initializeDatabases());  // Fire and forget
}, [dispatch]);
```

**HomeScreen.tsx:**
```typescript
useEffect(() => {
  if (dbInitialized) {
    dispatch(fetchBooksPage({limit: 20, offset: 0}));
    dispatch(fetchCatalogStats());
  }
}, [dispatch, dbInitialized]);
```

**Loading UI:** Show ActivityIndicator + "Initializing catalog..." or "Loading catalog..." when `!dbInitialized`. [Source: docs/prd/epic-10.md]

### File Locations

- `GrqaserApp/App.tsx` — add initializeDatabases dispatch.
- `GrqaserApp/src/screens/HomeScreen.tsx` — remove init call; conditional fetch.
- `GrqaserApp/src/components/AppLoadingScreen.tsx` (new) — loading component.
- `GrqaserApp/src/state/slices/databaseSlice.ts` — existing; dbInitialized, loading, error. [Source: architecture/source-tree.md]

### Success Metrics

- Time to first render: <2s (target).
- Startup time (network available): <5s (Phase 1 target). [Source: docs/prd/epic-10.md]
