# Story 10.5: Performance Testing Plan and Optimization (2000 Books)

## Status

Draft

## Story

**As a** product owner / developer,
**I want** a performance testing plan using a catalog of 2000 books, with metrics per feature and targeted optimizations,
**so that** we can validate and improve performance at scale and avoid regressions.

## Acceptance Criteria

1. **Testing plan:** A documented performance testing plan is created that uses a dataset of 2000 books (or equivalent load).
2. **Metrics per feature:** The plan defines or updates metrics for each relevant feature (e.g., app launch, search, Library load, list scroll, cover loading).
3. **Baseline and targets:** Baseline metrics are captured (or updated) and improvement targets are set where applicable.
4. **Optimization work:** Identified bottlenecks from the plan are addressed with code or configuration changes to meet targets where feasible.
5. Results and any remaining limits are documented for future reference.

## Tasks / Subtasks

- [ ] Task 1: Create performance testing plan document (AC: 1, 2)
  - [ ] Create a plan (e.g., in docs/) that describes how to run the app with 2000 books (seed DB or use test DB)
  - [ ] List features to measure: app launch (time to interactive), search (time to first result, scroll FPS), Library load, list scroll, cover image load
  - [ ] Define how each metric is measured (e.g., manual timing, FPS overlay, React DevTools, or instrumentation)

- [ ] Task 2: Define baselines and targets (AC: 3)
  - [ ] Run baseline measurements with 2000-book dataset and record current values
  - [ ] Set improvement targets (e.g., launch < Xs, scroll 60fps) where applicable
  - [ ] Document baselines and targets in the plan

- [ ] Task 3: Execute optimizations based on plan (AC: 4)
  - [ ] Prioritize bottlenecks (e.g., launch, list render, cover load) and apply fixes (lazy load, virtualization, caching, DB queries)
  - [ ] Re-run measurements and confirm improvements; iterate if needed
  - [ ] Coordinate with Stories 10.1 and 10.6 for launch and cover optimizations

- [ ] Task 4: Document results and limits (AC: 5)
  - [ ] Update the plan or a results doc with before/after metrics and any remaining limits or known issues

## Dev Notes

### Context

Previous stories may have been implemented in a hurry; this story adds a structured performance test with 2000 books, updates metrics per feature, and drives optimizations. Complements 10.1 (launch/lazy load) and 10.6 (cover lazy load/memory).

### Relevant Source Tree

```
GrqaserApp/
├── docs/                  ← add performance-testing-plan.md (or similar)
├── (test data)            ← 2000-book DB or seed script
└── (instrumentation)     ← optional: timing logs, FPS checks
```

### Key Points

- **2000-book dataset:** May require a seed script or a pre-built test DB; document how to obtain and load it.
- **Metrics:** At minimum cover: cold start time, time to interactive, search response time, list scroll FPS, cover load (e.g., time to first paint for first N covers).
- **Optimization:** Use findings from 10.1 and 10.6; add list virtualization (e.g., FlatList with windowing) if not already in place; ensure DB queries are indexed and minimal.

### Testing

- Follow the plan to run with 2000 books; record metrics; verify optimizations improve or meet targets.
- Document any limits (e.g., "scroll FPS drops on very old devices") for future reference.
