# Story 10.6: Book Cover Images — Lazy Load and Memory Cleanup

## Status

Done

## Story

**As a** mobile user and as a platform,
**I want** book cover images to load lazily and not be kept in memory indefinitely,
**so that** the app stays responsive and does not run out of memory with large catalogs.

## Acceptance Criteria

1. **Lazy load covers:** Book cover images are loaded on demand (e.g., when visible or when entering a screen), not preloaded for the entire catalog.
2. **Memory cleanup:** The app uses a smart cleanup strategy (e.g., limit cached images, evict off-screen or least-recently-used covers) so that memory used for cover images is bounded and released when appropriate.
3. **No full catalog in memory:** Cover image data is not retained for all books in memory at once; only a reasonable subset is cached.
4. Scrolling and navigation remain smooth; covers may re-load when returning to a list if they were evicted, with acceptable UX (e.g., placeholder then load).

## Dev Notes

### Context

Book cover images should be lazy-loaded and not kept in memory for the entire catalog. Use smart cleanup (bounded cache, LRU or visibility-based eviction) so memory stays under control with 2000+ books.

### Relevant Source Tree

```
GrqaserApp/src/
├── components/            ← BookCard, cover image component
├── (image library)        ← e.g., react-native-fast-image or Image + cache
├── state/ or services/    ← optional: image cache service
└── screens/               ← lists that render covers (Home, Search, Library, Favorites)
```

### Key Points

- **Lazy load:** Use list virtualization (FlatList) so only visible items mount; image component should load `uri` when the item is visible, not on initial app load.
- **Cache:** If using `react-native-fast-image` or similar, configure max cache size; otherwise implement a simple in-memory cache with max count/MB and LRU eviction.
- **Eviction:** When user scrolls far, evict images that are no longer visible; when user navigates to another tab, consider evicting or reducing cache for the previous list.
- **Placeholder:** Show a consistent placeholder while loading or after eviction until re-fetched.

### Testing

- With 500+ books, scroll through list: memory should not grow unbounded (use Xcode/Android profiler or similar).
- Navigate away and back: covers may re-load (placeholder then image); no crash.
- Scrolling remains smooth (e.g., 60fps or acceptable on target devices).
