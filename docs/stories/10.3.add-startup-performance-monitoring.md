# Story 10.3: Add Startup Performance Monitoring

## Status

Draft

## Story

**As a** developer,
**I want** to measure and monitor app startup performance,
**so that** I can identify bottlenecks and track improvements.

## Acceptance Criteria

1. Performance timing utilities created
2. App initialization phases instrumented
3. Database operations instrumented
4. Startup metrics logged to console (dev) or analytics (prod)
5. Performance dashboard available in dev mode

## Tasks / Subtasks

- [ ] Task 1: Add performance timing utilities (AC: 1)
  - [ ] Create `GrqaserApp/src/utils/performanceMonitor.ts` (or equivalent).
  - [ ] Implement `mark(name)` and `measure(name, startMark, endMark?)` methods.
  - [ ] Store marks and measures; log to console in __DEV__.
  - [ ] Support `getMeasures()` for dashboard. See epic PerformanceMonitor class. [Source: docs/prd/epic-10.md#Performance-Monitoring]

- [ ] Task 2: Instrument app initialization (AC: 2)
  - [ ] In App.tsx: call `perfMonitor.mark('app-mount')` on mount.
  - [ ] After NavigationContainer onReady: `perfMonitor.mark('navigation-ready')` and `perfMonitor.measure('Time to Navigation Ready', 'app-mount', 'navigation-ready')`.
  - [ ] After initializeDatabases fulfills: `perfMonitor.measure('Database Initialization', 'app-mount')`.
  - [ ] Log measures in __DEV__. [Source: docs/prd/epic-10.md#Usage-Example]

- [ ] Task 3: Instrument database operations (AC: 3)
  - [ ] In databaseSlice or databaseManager: mark start/end for initAppMetaDb, fetchManagedDatabases, initCatalogDb.
  - [ ] Measure each phase: "App Meta DB Init", "Fetch Managed DBs", "Catalog DB Init".
  - [ ] Log per-phase timings. [Source: docs/prd/epic-10.md]

- [ ] Task 4: Add startup metrics logging (AC: 4)
  - [ ] In __DEV__: console.log all measures (e.g. "[Perf] Database Initialization: 2400ms").
  - [ ] In prod: optionally send to analytics (fire-and-forget) if analytics service exists; else skip or minimal log.
  - [ ] Ensure no PII or sensitive data in logs. [Source: docs/prd/epic-10.md]

- [ ] Task 5: Create performance dashboard (AC: 5)
  - [ ] In dev mode: add a simple in-app overlay or screen (e.g. dev menu) that shows `getMeasures()` as a list or table.
  - [ ] Optional: trigger via shake gesture or __DEV__ flag.
  - [ ] Display: mark name → duration (ms). [Source: docs/prd/epic-10.md]

- [ ] Task 6: Unit tests
  - [ ] Test performanceMonitor mark/measure logic.
  - [ ] Test that measures are recorded correctly.
  - [ ] Run `npm test` from GrqaserApp. [Source: architecture/testing-and-deployment-strategy.md]

## Dev Notes

### PerformanceMonitor API

```typescript
class PerformanceMonitor {
  mark(name: string): void;
  measure(name: string, startMark: string, endMark?: string): number;
  getMeasures(): Record<string, number>;
  reset(): void;
}
```

- In __DEV__, log each mark and measure to console. [Source: docs/prd/epic-10.md#Performance-Monitoring]

### Usage in App.tsx

```typescript
useEffect(() => {
  perfMonitor.mark('app-mount');
  dispatch(initializeDatabases()).then(() => {
    perfMonitor.measure('Database Initialization', 'app-mount');
  });
}, [dispatch]);

// NavigationContainer onReady
onReady={() => {
  perfMonitor.mark('navigation-ready');
  perfMonitor.measure('Time to Navigation Ready', 'app-mount', 'navigation-ready');
}}
```

[Source: docs/prd/epic-10.md]

### Metrics to Capture

- Time to Navigation Ready (app-mount → navigation-ready)
- Database Initialization (app-mount → init complete)
- Per-phase: App Meta DB, Fetch Managed DBs, Catalog DB Init. [Source: docs/prd/epic-10.md]

### File Locations

- `GrqaserApp/src/utils/performanceMonitor.ts` (new)
- `GrqaserApp/App.tsx` — instrument mount and navigation
- `GrqaserApp/src/state/slices/databaseSlice.ts` — instrument DB phases (or databaseManager)
- Optional: `GrqaserApp/src/components/PerformanceDashboard.tsx` for dev overlay [Source: architecture/source-tree.md]

### Success Metrics

- Visibility into performance bottlenecks.
- Manual testing: measure TTFR and TTI on device. [Source: docs/prd/epic-10.md#Performance-Benchmarks]
