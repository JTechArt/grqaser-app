# Story 10.3: Favorites Section — Align Layout with Search

## Status

Draft

## Story

**As a** mobile user,
**I want** the Favorites section to use the same layout as the Search results screen,
**so that** the design is consistent and the Favorites view is as clear and usable as Search.

## Acceptance Criteria

1. **Layout alignment:** The Favorites section uses the same layout and visual structure as the Search screen (e.g., grid/list, spacing, card size, padding).
2. **Consistent UX:** Interaction patterns (tap to open book, empty state, etc.) align with Search where applicable.
3. No regression in Favorites functionality (add/remove favorite, open book).

## Tasks / Subtasks

- [ ] Task 1: Audit Search screen layout and components (AC: 1)
  - [ ] Document Search results layout: grid vs list, columns, card size, spacing, padding
  - [ ] Identify reusable components (e.g., BookCard, grid container) used on Search

- [ ] Task 2: Refactor Favorites to use same layout as Search (AC: 1, 2)
  - [ ] Replace Favorites-specific layout with the same structure as Search (same grid/list, same card component and styling)
  - [ ] Align empty state and interaction patterns (tap to open book) with Search where applicable
  - [ ] Reuse or share styles/components between Search and Favorites to avoid drift

- [ ] Task 3: Verify no regressions (AC: 3)
  - [ ] Confirm add/remove favorite still works; opening a book from Favorites works
  - [ ] Confirm Favorites list updates when user adds/removes favorites

## Dev Notes

### Context

Favorites section design is not as good as Search; product request is to use the same layout as Search for consistency and better UX.

### Relevant Source Tree

```
GrqaserApp/src/
├── screens/
│   ├── SearchScreen.tsx   ← reference layout
│   └── FavoritesScreen.tsx ← update to match
├── components/            ← shared BookCard, grid, etc.
└── styles/ or theme      ← spacing, card size
```

### Key Points

- **Search as source of truth:** Copy or reuse the same grid configuration (e.g., numColumns, item width, gap), card component, and padding from SearchScreen.
- **Favorites data:** Only the data source differs (favorites list vs search results); the presentation should be the same.
- **Empty state:** If Search has an empty state style, mirror it on Favorites for "No favorites yet."

### Testing

- Visual comparison: Favorites and Search (with one result) should look like the same layout.
- Functional: Add/remove favorite, open book from Favorites; no regressions.
