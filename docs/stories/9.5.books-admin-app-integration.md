# Story 9.5: Books Admin App Integration

## Status

Done

## Story

**As an** administrator,
**I want** to manage authors and categories separately and use advanced filters,
**so that** I can maintain data quality and find books efficiently.

## Acceptance Criteria

1. Authors management UI (list, add, edit, delete)
2. Categories management UI (list, add, edit, delete)
3. Book edit form uses dropdowns for author/category selection
4. Book list has advanced filters (author, category, duration, text)
5. Crawler automatically populates authors and categories tables
6. API routes for authors/categories CRUD operations

## Dev Notes

### Dependencies

- **Story 9.1** must be complete (authors, book_categories tables, FK on books).
- **Story 9.2** provides GET /api/v1/authors and GET /api/v1/categories; this story adds CRUD.

### Admin UI Features

**Authors:** List with search/pagination, add form, edit, delete (prevent if books exist), book count.  
**Categories:** Same.  
**Book Edit:** Searchable dropdowns for author and category; optional inline create.  
**Book List Filters:** Author multi-select, category multi-select, duration range, text search. [Source: docs/prd/epic-9.md]

### File Locations

- `books-admin-app/src/routes/` — authors, categories CRUD routes.
- `books-admin-app/public/` — web UI (authors, categories, book edit, book list filters).
- `books-admin-app/src/crawler/` — crawler logic to upsert authors/categories. [Source: architecture/books-admin-app-architecture.md]

### Crawler Updates

- On book insert: INSERT OR IGNORE into authors (name), get id; same for book_categories; set books.author_id, books.category_id.
- Use TRIM, handle 'Unknown Author' and 'Unknown' per migration logic. [Source: docs/architecture/epic-9-schema-changes.md]

### Testing

- Jest/Supertest for API. Integration tests for crawler + DB. [Source: architecture/testing-and-deployment-strategy.md]
