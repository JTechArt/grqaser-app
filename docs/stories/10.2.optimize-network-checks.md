# Story 10.2: Optimize Network Checks

## Status

Draft

## Story

**As a** developer,
**I want** to identify and optimize network-related operations during startup,
**so that** network availability doesn't cause 30-second delays.

## Acceptance Criteria

1. All network operations during startup identified and documented
2. Timeouts added to prevent indefinite blocking
3. Non-critical network checks deferred until after UI renders
4. File system operations optimized (caching, lazy loading)
5. SQLite connections don't block on network checks

## Tasks / Subtasks

- [ ] Task 1: Audit network operations at startup (AC: 1)
  - [ ] Trace startup flow: App.tsx → initializeDatabases → initAppMetaDb, fetchManagedDatabases, initCatalogDb.
  - [ ] Document RNFS operations: exists(), stat(), readDir() — may timeout on slow network/storage.
  - [ ] Document SQLite openDatabase — may wait for file system.
  - [ ] Document startNetworkMonitor (NetInfo) — defer if it causes delays.
  - [ ] Create audit doc or inline comments. [Source: docs/prd/epic-10.md#Potential-Bottlenecks]

- [ ] Task 2: Add timeout to RNFS operations (AC: 2)
  - [ ] Create `withTimeout<T>(promise, timeoutMs, errorMessage)` utility in `GrqaserApp/src/utils/`.
  - [ ] Wrap RNFS.exists(), stat(), readDir() (or equivalent) with timeout (e.g. 5s).
  - [ ] On timeout, fail gracefully (e.g. assume file absent, log warning).
  - [ ] Use in database initialization path. [Source: docs/prd/epic-10.md#Optimization-2]

- [ ] Task 3: Optimize database file checks (AC: 4)
  - [ ] Cache RNFS results where safe (e.g. file existence) to avoid repeated blocking calls.
  - [ ] Lazy-load file checks where possible (defer until needed).
  - [ ] Consider parallel checks if multiple DB paths are validated.
  - [ ] Avoid redundant stat/readDir calls. [Source: docs/prd/epic-10.md]

- [ ] Task 4: Review SQLite connection timeout (AC: 5)
  - [ ] Ensure SQLite.openDatabase() does not block indefinitely.
  - [ ] Add timeout or use native timeout option if supported by react-native-sqlite-storage.
  - [ ] Ensure DB init doesn't wait on network (SQLite is local; only RNFS may be slow).
  - [ ] Document any SQLite timeout behavior. [Source: docs/prd/epic-10.md#Potential-Bottlenecks]

- [ ] Task 5: Defer network monitor initialization (AC: 3)
  - [ ] If startNetworkMonitor runs at App mount, defer by 2 seconds: `setTimeout(() => startNetworkMonitor(), 2000)`.
  - [ ] Return cleanup that clears the timeout and stops the monitor.
  - [ ] Ensures UI renders before network monitor init. [Source: docs/prd/epic-10.md#Optimization-3]

- [ ] Task 6: Document and apply timeouts in databaseSlice (AC: 2)
  - [ ] Wrap initAppMetaDb, fetchManagedDatabases, initCatalogDb (or equivalent) with withTimeout.
  - [ ] Suggested: 5s for app meta, 5s for fetch managed DBs, 5s for catalog init; 3s for bundled catalog.
  - [ ] On timeout, reject with clear message; databaseSlice sets error state.
  - [ ] See epic code example for databaseSlice. [Source: docs/prd/epic-10.md#Optimization-2]

- [ ] Task 7: Unit tests
  - [ ] Test withTimeout utility.
  - [ ] Test initialization with mocked slow RNFS (optional).
  - [ ] Run `npm test` from GrqaserApp. [Source: architecture/testing-and-deployment-strategy.md]

3. **Network Monitor:** startNetworkMonitor() — defer.

### withTimeout Utility

```typescript
export function withTimeout<T>(
  promise: Promise<T>,
  timeoutMs: number,
  errorMessage = 'Operation timed out'
): Promise<T> {
  return Promise.race([
    promise,
    new Promise<T>((_, reject) =>
      setTimeout(() => reject(new Error(errorMessage)), timeoutMs)
    ),
  ]);
}
```

### Defer Network Monitor

```typescript
useEffect(() => {
  const timerId = setTimeout(() => {
    const stop = startNetworkMonitor();
    return () => { clearTimeout(timerId); stop(); };
  }, 2000);
  return () => clearTimeout(timerId);
}, []);
```
